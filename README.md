# 풍운록 — 자가 검증·자가 보완형 "바람의나라 스타일" MMORPG 생성 프롬프트

코딩 에이전트(Claude Code)가 **스스로 만들고 → 검증하고 → 실패 원인을 고치는 과정을 결과가 나올 때까지 반복**하도록
설계한 프롬프트와 실행 하네스입니다.

```
┌──────────────┐   프롬프트 + 직전 실패 로그   ┌──────────────────┐
│ run-until-   │ ─────────────────────────▶ │ 에이전트(claude -p)│
│ done.sh      │                            │ 계획→테스트→구현→   │
│ (바깥 루프)   │ ◀───── game/ 코드·커밋 ───── │ verify→자기비판     │
└──────┬───────┘                            └──────────────────┘
       │ node harness/judge.mjs  (에이전트와 독립된 외부 심판)
       ▼
  통과 2회 연속 + DONE 파일 → 종료   /   실패 → 로그를 다음 반복에 주입 (3회 동일 실패 시 "접근 변경" 지시)
```

## 파일 구성

| 파일 | 역할 |
|---|---|
| `prompts/baram-master-prompt.md` | 마스터 프롬프트. 역할, 가드레일, 기술 스택, 수용 기준 AC-01~20, 완료 정의, 프로토콜 계약, 작업 루프, 스턱 감지 규칙, 상태 보고 형식 |
| `harness/judge.mjs` | 외부 심판. 의존성 없이 Node 22로 게임을 설치·`npm run verify`·실행한 뒤 WebSocket으로 직접 접속해 검사 |
| `harness/run-until-done.sh` | 바깥 루프. 에이전트 실행 → 심판 → 실패 피드백 주입을 반복 |

## 이중 검증 구조

1. **내부 검증(에이전트 자신)** — 프롬프트가 AC마다 테스트를 먼저 쓰게 하고(`AC-xx`를 테스트 이름에 포함),
   `npm run verify`가 테스트 결과에서 `verify-report.json`을 자동 생성하게 합니다. 매 반복 자기 비판 체크리스트(뮤테이션 점검 포함)를 수행합니다.
2. **외부 검증(심판)** — 에이전트의 자기 보고를 믿지 않고 직접 확인합니다.
   - 정적: 필수 스크립트, AC별 테스트 존재, `skip/only/todo` 금지, 테스트 수 감소 금지, 원작 명칭 사용 금지
   - 파이프라인: `npm ci` → `npm run verify` 종료코드, 이번 실행에서 생성된 리포트인지, AC 20개 전부 pass, 실패·스킵 0
   - 라이브: 서버 기동·`/health`, 두 클라이언트 로그인, 상호 가시성, 1칸 이동과 1초 내 전파, 이동 속도 제한,
     채팅 전파·검증, 악성 입력 내성, **서버 재시작 후 캐릭터 위치 유지**
3. **하네스 무결성** — 에이전트가 `harness/`를 수정하면 감지해 git으로 되돌리고 `violations.log`에 남깁니다.
   심판 실패 상태에서 에이전트가 만든 `DONE`은 삭제합니다.

## 사용법

### A. 자동 루프 (권장 — 격리된 컨테이너/VM에서 실행)

```bash
git init && git add -A && git commit -m "init"   # 하네스 원복에 git이 필요
harness/run-until-done.sh 30                      # 최대 30회 반복
```

기본 플래그는 `--permission-mode bypassPermissions`입니다. 권한 확인 없이 명령을 실행하므로 **반드시 격리된 환경에서만** 쓰세요.
바꾸려면 `CLAUDE_FLAGS="--permission-mode acceptEdits" harness/run-until-done.sh`처럼 지정합니다.
연속 통과 기준은 `REQUIRED_STREAK`(기본 2)로 조정합니다.

### B. 수동

`prompts/baram-master-prompt.md` 전체를 Claude Code 세션에 붙여 넣습니다. 에이전트는 프롬프트 안의 루프에 따라
`node harness/judge.mjs`까지 스스로 실행하며 완료 정의를 채웁니다.

## 하네스 자체 검증 결과

심판이 정상 게임은 통과시키고 결함은 잡아내는지, 프로토콜을 구현한 모의 서버로 확인했습니다.

| 주입한 결함 | 심판 결과 |
|---|---|
| 없음 (정상) | 21/21 통과 |
| 이동 속도 제한 제거 | L7 실패 (0.3초에 50칸 이동) |
| 저장 안 함 | L13 실패 (재시작 후 위치 초기화) |
| 빈 채팅 허용 | L9 실패 |
| 잘못된 JSON에 서버 크래시 | L11·L12·L13 실패 |
| `it.skip` 추가 + AC-20 테스트 삭제 | S4·S5·S6 실패 |
| 원작 명칭 사용 | S7 실패 |

가짜 에이전트로 루프 전체도 실행했습니다. 반복 1에서 L7 실패 → 실패 로그가 주입됨 → 반복 2에서 수정 → 심판 25/25 연속 2회 통과 → `DONE` 확인 후 종료.

## 저작권 주의

"바람의나라"는 넥슨의 상표이자 저작물입니다. 프롬프트는 원작 리소스·명칭을 쓰지 않고 분위기만 참고한 **창작 게임**
(기본 제목 "풍운록")을 만들도록 강제하며, 심판도 원작 명칭 사용을 검사합니다.
